Usage

Once the SAT app is deployed (see Installation), everything is driven from the app itself — there are no notebooks to import or dashboards to publish.

Open the app

Find it under Compute → Apps → security-analysis in your Databricks workspace, then click Open.

Step 1 — Complete first-run setup​

The first time you open the app it shows a setup screen. Provide:

  • Catalog & schema — where SAT stores its results. The app creates the schema and owns it. Pick a catalog you can access, or type any catalog name.
  • SQL warehouse — runs the analysis queries and alerts.
  • Account credentials (optional, for account-wide data) — an Account ID and a service principal's client ID + secret (that SP must hold the Account admin role). These unlock Account/Workspace/Metastore Admin detection, account users & groups, and other account-wide reports. They are stored as Unity Catalog secrets — no secret scope required. Without them, SAT reports on the current workspace only.
  • Collection scope & compute —
    • Workspaces to scan: this workspace only, or multiple workspaces. This governs both resource-permission collection and secret scanning: this workspace only restricts both to the current workspace; multiple workspaces covers every workspace the service principal administers. To add a workspace to the multi-workspace set, make the service principal a workspace admin there, then run Data Collection → Manage → Sync workspaces (see below). Identity and admin data is always account-wide when account credentials are set.
    • Job compute: serverless (recommended) or classic. Classic is offered when the workspace supports it; a genuinely serverless-only workspace shows classic as unavailable.
    • Scan notebook & folder permissions: off by default; turning it on walks the whole workspace tree so each collection run takes longer to complete.
Everything is reconfigurable

You can change any of these later from Settings (catalog/schema, warehouse, model, credentials) and Data Collection → Manage (scope, compute, notebook/folder collection). The collection jobs are re-provisioned automatically when you change compute or scope.

Adding or removing workspaces — Sync workspaces

Which workspaces SAT scans is driven by whether its service principal is a workspace admin of each one. After adding (or removing) the service principal as a workspace admin, open Data Collection → Manage → Sync workspaces: SAT lists the account's workspaces and enables the ones the service principal administers. It's an explicit, in-app action — no manual SQL and no re-running a collection job.

Scope and sync work together: switching collection scope to "Multiple workspaces" runs a sync for you, so the common first-time path is just picking Multiple. The standalone Sync workspaces button is for refreshing the set afterwards when you add or remove the service principal as an admin. If you Sync while scope is still "This workspace only," the extra workspaces are enabled but not scanned until you switch to Multiple — the app tells you so.

Step 2 — Run data collection​

On the Data Collection page you'll see SAT's collection jobs (initializer, permissions data collection, account reports, and the secret scanner). They run on a schedule, and you can trigger any of them on demand.

Collection can take several minutes per workspace, depending on account size.

The app owns the jobs

SAT creates and manages these jobs itself under the app's service principal. You don't import or schedule any notebooks — adjust the schedule, scope, and compute from the app.

Step 3 — View results​

All results are in the app:

  • Principal Analysis / Resource Analysis — who can access what, with escalation and impersonation risk. See Permissions Analysis.
  • Credential Exposure — hardcoded secrets in notebooks and cluster configs. See Secret Scanning.

Because the app queries as the signed-in user, Unity Catalog enforces each viewer's own grants — people see only the results they are entitled to.

Step 4 — Configure secret scanning (optional)​

On the Credential Exposure page, open Scan Settings & Custom Detection Rules to:

  • Scan coverage — scan all notebooks (recommended, so the view reflects your complete current exposure) or only notebooks modified in the last N days.
  • Custom detection rules — add your own patterns (name, keywords, regex) on top of SAT's built-in detectors. Rules are listed as editable rows you can change or delete.

Changes are saved to the scanner's config and take effect on the next scan run — no redeploy and no editing notebooks. More detail on the Secret Scanning page.

Step 5 — Set up alerts (optional)​

On the Alerts page, create email/notification alerts on secret-scan findings (for example, "any hardcoded credential detected"). Pick the condition, how often to check, and who to notify. Alerts are standard Databricks SQL alerts, so they also appear under Alerts in the workspace and keep working if the app is ever removed.

Admins only

Creating, editing, and deleting alerts is restricted to workspace or account admins. Other users can view alerts and run the read-only "test condition" check, but the create/edit/delete controls are hidden for them.
