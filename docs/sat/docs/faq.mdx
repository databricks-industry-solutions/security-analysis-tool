# FAQ

Welcome to the SAT Frequently Asked Questions. Click on any question to expand and view the answer.

## SAT Deployment and Support

<AccordionItem question="Is SAT an officially supported tool?">

The **Security Assessment Tool (SAT)** is not officially supported by Databricks. It is provided **as-is** under the Databricks License, with no guarantees or Service Level Agreements (SLAs). Please do not open support tickets for issues related to SAT. Instead, report any problems or feature requests by creating a GitHub Issue on the project's repository. Issues will be reviewed as time permits. All third-party libraries referenced are subject to their respective licenses.

</AccordionItem>

<AccordionItem question="Can I open Databricks support tickets if I encounter issues with SAT?">

Currently, SAT is a self-service tool which is developed and maintained by the Databricks field team. If you encounter any issues, please contact your Databricks account team and submit a GitHub issue on the project's repository.

</AccordionItem>

<AccordionItem question="Can SAT be configured on an independent virtual machine?">

SAT needs to be deployed in one of your Databricks workspaces and run as a workflow. You can trigger the SAT installation process from any machine (preferably Linux) where the Databricks CLI and other prerequisites are available, installed and configured.

</AccordionItem>

<AccordionItem question="Does SAT automatically update once I set up?">

SAT is frequently updated and the latest versions are made available in the official GitHub repository. SAT deployments do not automatically update on their own. To upgrade or update SAT deployments in your environment, you will need to perform the update manually. This design decision is by choice, so that customers have full control on the upgrade process of SAT.

</AccordionItem>

<AccordionItem question="Can SAT make modifications to my workspaces and account?">

SAT is read-only by default — it analyzes and reports, and does not change your workspace or account configurations. The only changes it can make are ones you explicitly opt into: creating SQL alerts, and the opt-in remediation in a few account reports (for example removing an over-broad "shared to all account users" grant or an unexpected admin role), which run only when you turn them on.

</AccordionItem>

<AccordionItem question="I am seeing errors when I run the SAT. How can I validate my SAT configuration?">

Use the app's built-in requirements check: open **Settings → Re-run setup** and review the requirements checklist, which verifies the account connection and the service principal's **Account admin** role live and flags configuration gaps. For a failed collection job, open the **Data Collection** page and inspect that job's last run. See [Troubleshooting](./troubleshooting.mdx).

</AccordionItem>

<AccordionItem question="If SAT is already configured, how do we add/remove other workspaces in the same account/subscription?">

Scan coverage is driven by whether the SAT service principal is a **workspace admin** of each workspace. To include a workspace, add the service principal as a workspace admin on it; to exclude one, remove it. Then open **Data Collection → Manage → Sync workspaces** in the app — Sync discovers the account's workspaces and enables the ones the service principal administers (`analysis_enabled` in the `account_workspaces` table). No manual SQL, no re-running a heavy collection job. Make sure collection scope is **Multiple workspaces** for the scanners to cover more than the current workspace.

</AccordionItem>

<AccordionItem question="A workspace was deleted after SAT was set up — how do I stop it from erroring?">

A workspace that can no longer be reached fails its connection test on the next scan and is **skipped and recorded**, not failed — no reinstall needed. To drop it from the registry entirely, run **Data Collection → Manage → Sync workspaces** (Sync only keeps **RUNNING** account workspaces the service principal administers).

</AccordionItem>

<AccordionItem question="I added a new workspace — how do I get it included?">

Add the app's service principal as a **workspace admin** on the new workspace, then run **Data Collection → Manage → Sync workspaces** so SAT discovers it and enables it for scanning. Set collection scope to **Multiple workspaces** so the scanners cover it. No re-setup, no initializer re-run, and no dashboard pulldown or cache to refresh. (Removing the service principal as admin and syncing again drops the workspace.)

</AccordionItem>

<AccordionItem question="Can I use one deployment of SAT to monitor all my workspaces across different clouds, like AWS and Azure?">

A single SAT app monitors all workspaces in the same **Databricks account** — on AWS, Azure, or GCP. (On Azure this is per Databricks account, not per subscription.) A different Databricks account — for example a separate AWS account and Azure account — needs its own SAT app.

</AccordionItem>

<AccordionItem question="Do I need different SAT deployment to monitor workspaces in different regions?">

A single SAT app monitors all workspaces in the same **Databricks account** regardless of region, on any cloud.

</AccordionItem>

<AccordionItem question="Can SAT be integrated with other cloud based monitoring tools?">

SAT is designed specifically for Databricks. Its results live as Delta tables in your chosen Unity Catalog schema, so you can query or export them with any tool that reads Unity Catalog (DBSQL, BI tools, pipelines) and feed them into other systems as needed.

</AccordionItem>

<AccordionItem question="Is SAT supported on AWS GovCloud?">

Yes. SAT supports AWS GovCloud (FedRAMP) and AWS DoD IL5 — it resolves the correct account-console host for each (`accounts.cloud.databricks.us` for GovCloud, `accounts-dod.cloud.databricks.mil` for DoD) — in addition to commercial AWS, Azure, and GCP.

</AccordionItem>

## SAT Reports

<AccordionItem question="Do we need to address every finding SAT reports?">

Review SAT's findings with your business stakeholders, administrators, security team, and auditors, and assess them against your organizational security requirements — not every finding requires action, and some remediations have cost or dependency implications. Always review the associated feature documentation before making changes.

</AccordionItem>
