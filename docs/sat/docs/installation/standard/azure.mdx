# Azure Installation

This guide will walk you through setting up the **Security Analysis Tool (SAT)** on Azure Databricks.

<Admonition type="warning" title="Unity Catalog Required">
**SAT requires Unity Catalog.** Make sure Unity Catalog is enabled in your Databricks environment before installing SAT.
</Admonition>

<Admonition type="info" title="Azure Subscription">
One SAT app per **Databricks account** monitors all its workspaces, across subscriptions — a separate per-subscription deployment is no longer needed.
</Admonition>

<Admonition type="tip" title="Best for Premium & Enterprise Tiers">
SAT is especially beneficial to customers on Databricks **Premium** or **Enterprise** tiers, where Unity Catalog and the richer access controls SAT analyzes are available.
</Admonition>

## Prerequisites

Before you begin, ensure you have:

- ✅ Reviewed the [general prerequisites](../../installation/index.mdx#prerequisites)
- ✅ Appropriate permissions in your Azure cloud account
- ✅ A metastore attached to your installation workspace
- ✅ Databricks CLI installed and configured
- ✅ **Python 3.9 or higher** (3.9–3.12, for running the local installer)

---

## Step 1: Create Service Principal

The service principal lets SAT authenticate to the Databricks account and workspace APIs to collect security information.

<Admonition type="info" title="Databricks OAuth — no Microsoft Entra / tenant needed">
SAT authenticates with **Databricks OAuth**, the same way it does on AWS and GCP. It reads only the Databricks account and workspace APIs, so there is **no Microsoft Entra (Azure AD) token, no tenant ID, and no Azure subscription** involved. You give the service principal a **Databricks OAuth secret** (not an Azure AD app client secret).
</Admonition>

<AccordionItem question="How to create a Service Principal">

**Follow these steps in the Databricks Account Console:**

1. Navigate to the [Databricks Account Console](https://accounts.azuredatabricks.net/)
2. Click on `User management` in the left sidebar
3. Select `Service principals` → `Add service principal`
4. Choose **Databricks managed**, enter a name (e.g., "SAT-Service-Principal"), and click `Add`
   - If you prefer to use an existing **Microsoft Entra ID** application, choose *Microsoft Entra ID managed* instead and paste its Application (client) ID. Either kind works — SAT only needs the Databricks OAuth secret created in Step 2.
5. Grant the `Account Admin` role
6. Assign the `Workspace Admin` role for each workspace to be monitored
7. Add to the `Metastore Admin` group or role
8. Add the Service Principal to each workspace you want to analyze

<div className='bg-gray-100 p-4 rounded-lg mb-6'>
  <img src={useBaseUrl('/img/azure_role_assignment.png')} alt="Role Assignment" />
</div>

**Required Permissions:**
- [Account Admin role](https://learn.microsoft.com/en-us/azure/databricks/admin/users-groups/service-principals#--assign-account-admin-roles-to-a-service-principal)
- [Workspace Admin role](https://learn.microsoft.com/en-us/azure/databricks/admin/users-groups/service-principals#assign-a-service-principal-to-a-workspace-using-the-account-console) for **each workspace**
- [Metastore admin group](https://learn.microsoft.com/en-us/azure/databricks/data-governance/unity-catalog/manage-privileges/admin-privileges#who-has-metastore-admin-privileges) membership

</AccordionItem>

## Step 2: Create a Databricks OAuth Secret

<AccordionItem question="How to create the OAuth secret">

**In the Databricks Account Console:**

1. Open the service principal you created in Step 1
2. Go to the `Secrets` section → under **OAuth secrets**, click `Generate secret`
3. **Copy and save the `Secret` and the `Client ID`** immediately (the secret is shown only once)

This is a **Databricks** OAuth secret, used with the standard `client_id` / `client_secret` OAuth flow — the same model as AWS and GCP. You do **not** create an Azure AD "Certificates & secrets" client secret.

📚 [Learn more about Databricks OAuth (M2M) for service principals](https://learn.microsoft.com/en-us/azure/databricks/dev-tools/auth/oauth-m2m)

</AccordionItem>

## Step 3: Run Installation

<Admonition type="note" title="Credentials Required">
Have these ready for the app's **in-app setup** (you enter them in the app after install, not during `install.sh`):

- 🔑 **Databricks Account ID**
- 🔑 **Service Principal Client ID** (from Step 1)
- 🔑 **Databricks OAuth Secret** (from Step 2)

No Azure tenant ID or subscription ID is needed.
</Admonition>

### Installation Steps

Run these commands on your workstation or a VM with internet access and Databricks workspace connectivity:

**1. Clone the SAT repository:**

```sh
git clone https://github.com/databricks-industry-solutions/security-analysis-tool.git
cd security-analysis-tool
```

<Admonition type="warning" title="Databricks CLI Required">
Make sure the target workspace has a [profile configured](https://docs.gcp.databricks.com/en/dev-tools/cli/profiles.html) in the [Databricks CLI](https://docs.gcp.databricks.com/en/dev-tools/cli/tutorial.html).
</Admonition>

**2. Make the installation script executable and run it:**

```sh
chmod +x install.sh
./install.sh
```

<Admonition type="tip" title="Proxy Support">
**Proxies are supported!** You can add your HTTP and HTTPS proxy values during the install.sh script when prompted.
</Admonition>

**3. Follow the interactive prompts:**

The installation script will guide you through the setup process. Here's what it looks like:

<Admonition type="note" title="Finish setup in the app">
After `install.sh` deploys the app, open it (**Compute → Apps → security-analysis**) and complete the in-app setup — results catalog/schema, SQL warehouse, and (optionally) account credentials for account-wide data. Permissions Analysis is built into the app; there is no separate app to configure.
</Admonition>

<Admonition type="info" title="Deploying the app — choose the source folder">
`install.sh` uploads the app code to **`/Workspace/Applications/SAT/files/app/security-analysis-tool`** and deploys it for you. If you ever deploy or redeploy from the **Databricks Apps UI** (Compute → Apps → security-analysis → Deploy), you must select that folder as the app's **source code path**. From the CLI the equivalent is `databricks apps deploy security-analysis --source-code-path /Workspace/Applications/SAT/files/app/security-analysis-tool`.
</Admonition>

<Admonition type="tip" title="Scanning multiple workspaces">
To cover more than the workspace SAT is installed in, add the SAT service principal as a **workspace admin** on each workspace you want scanned, then in the app open **Data Collection → Manage**, set **Compute & scope** to **Multiple workspaces** (switching to Multiple runs a workspace sync for you), and confirm the panel's "Will scan: N workspaces" count. Use **Manage → Sync workspaces** any time you later add or remove the service principal as an admin. See the [usage guide](../../usage.mdx) for the full workflow.
</Admonition>

Congratulations! 🎉 You've successfully installed SAT on Azure Databricks.

<Admonition type="success" title="Installation Complete">
SAT is now ready to analyze your Databricks workspaces. Click [here](../../../functionality) for a detailed guide on how to run and use it.
</Admonition>

## Need Help?

<AccordionItem question="Troubleshooting Installation Issues">

If you encounter problems during installation:

**Common Issues:**
- ✓ Double-check your credentials are correct — the client secret must be a **Databricks OAuth secret** (Step 2), not an Azure AD "Certificates & secrets" client secret
- ✓ Verify the Service Principal has **Account Admin** (and **Workspace Admin** on each workspace)
- ✓ Ensure the Service Principal has been added to all workspaces
- ✓ Confirm the metastore is attached to your workspace

**Resources:**
- Review our [FAQ page](../../faq.mdx) for common questions
- Use the in-app requirements check (**Settings → Re-run setup**) to verify your setup
- Check the [troubleshooting guide](../../troubleshooting.mdx) for specific errors

**Still need help?** Contact us at sat@databricks.com

</AccordionItem>
