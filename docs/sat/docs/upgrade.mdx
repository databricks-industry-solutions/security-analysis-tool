# Upgrading SAT

SAT does not auto-upgrade. To pick up a new version, redeploy the app from the
updated source — your configuration and already-collected data are preserved.

## Upgrading an existing app install

1. Get the latest code (`git pull` on your checkout, or re-download the release).
2. Redeploy with your usual path:
   - **Standard install:** rerun `./install.sh`.
   - **Terraform:** `terraform apply` against the updated module.
   - **DABS bundle (advanced):** `databricks bundle deploy` from the repo root.
3. In the app, open **Data Collection → Manage → Redeploy jobs** so the collection
   jobs use the new bundled notebooks.

<Admonition type="tip" title="Your settings and data survive">
Configuration lives in the app's config file and credentials in Unity Catalog
secrets; collected results live in your results schema. Redeploying the app or
jobs does not clear them. "Redeploy jobs" updates the job definitions/notebooks;
"Re-run initializer" rebuilds the result tables' schema without dropping prior
runs.
</Admonition>

<Admonition type="note" title="Network-policy / egress changes">
If a redeploy changes the app's network policy or egress, **stop and start** the
app (not just redeploy) so the new network settings take effect.
</Admonition>

## Moving from a pre-1.0 (classic) install

Versions before 1.0 ran SAT as a set of notebooks (Initializer + Driver) with
standalone Lakeview dashboards. **1.0 replaces both with the single SAT app.**
After deploying 1.0:

- Use the app for everything — findings, permissions, secrets, and alerts. The
  old **General** and **Executive** Lakeview dashboards are retired.
- Complete the app's first-run setup (catalog/schema, warehouse, and optionally
  account credentials). You can point it at your existing results schema.
- Retire the old **SAT Initializer Notebook** / **SAT Driver Notebook** workflows
  — the app provisions and schedules its own collection jobs.

<Admonition type="info" title="Re-consent for per-user authorization">
The app queries as the signed-in user (on-behalf-of) so Unity Catalog enforces
each viewer's grants. Users who opened an earlier app build before user
authorization was configured re-consent once — see
[Permissions Analysis → Re-consent after an upgrade](./functionality/permissions-analysis.mdx)
and [Troubleshooting](./troubleshooting.mdx).
</Admonition>
