# The SAT App

As of **1.0**, SAT is a single **Databricks App**. Everything — first-run setup,
data collection, permissions analysis, secret scanning, alerts, and the security
assistant — lives in one interface.

<Admonition type="tip" title="What's retired in 1.0">
The standalone dashboards (General and Executive), the Initializer/Driver
notebook workflow, and the configuration-vs-best-practice **security checks** are
no longer part of SAT. 1.0 focuses on **access/permissions risk** and **exposed
secrets**. Open the app from **Compute → Apps → security-analysis** and you have
the whole tool in one place.
</Admonition>

## How the app is organized

* **Home** — a landing overview of your account's scope (workspaces, account
  groups and admins) and quick entry points into the analyses below.
* **Principal Analysis** — start from a user, group, or service principal and see
  everything it can reach, with admin roles (Account / Workspace / Metastore
  Admin, Catalog Owner) and the workspaces/metastores each admin administers.
* **Resource Analysis** — start from a resource (catalog, schema, table, cluster,
  job, warehouse, secret scope, notebook, or folder) and see every principal that
  can reach it, and whether access is direct or inherited through a group.
* **Credential Exposure (secret scanning)** — hardcoded secrets found in notebook
  source and cluster configurations, with scan settings and custom detection
  rules. See [Secret Scanning](./cluster-secrets-scanning).
* **Alerts** — email/notification alerts on secret-scan findings, built on
  Databricks SQL alerts. Creating and editing alerts is restricted to workspace
  or account admins.
* **Security Assistant** — a chat assistant (backed by a Databricks Foundation
  Model and a Genie space) that answers questions about your findings and
  permissions, enforcing your own Unity Catalog grants on every answer.
* **Data Collection** — run and schedule the collection jobs on demand, and
  manage scan scope, compute, and notebook/folder collection (see the
  **Manage** panel).
* **Settings** — change the results catalog/schema, SQL warehouse, model, or
  account credentials at any time.

## Who sees what

The app runs queries **as the signed-in user** (on-behalf-of), so Unity Catalog
enforces each viewer's own grants on the results — people see only the data they
are entitled to. Administrative actions are gated accordingly: **creating,
editing, and deleting alerts requires the signed-in user to be a workspace or
account admin.**

<Admonition type="note" title="Access to the app itself">
Grant "Can Use" on the Databricks App only to the people who should operate SAT.
App access is the boundary for running collection jobs; viewing results is
further constrained per-user by Unity Catalog.
</Admonition>
